Android & Kotlin Glossary

The vocabulary used across the fokus-android repo, in one printable page. Each term notes where it lives in the repo.

This is the shared glossary for every lesson in this course. When a lesson introduces a term, it links here. New terms are added here as lessons introduce them.

The app & the build

TermMeaning
GradleThe build system. `build.gradle.kts` scripts compile, package, and sign the app. Config is centralized in gradle/libs.versions.toml (a "version catalog").
version cataloglibs.versions.toml — one place listing every dependency and plugin version, referenced as libs.androidx.compose.material3 etc.
namespace / applicationIdnamespace = Kotlin package root (dev.fokus.app); applicationId = unique install identity on the device.
minSdk / targetSdk / compileSdkminSdk = oldest Android version supported (24 = Android 7.0); targetSdk = version your app is validated against; compileSdk = API level you compile against (36).
Compose BOMBill of Materials — one version that pins all Compose library versions together so they stay compatible.

Platform components (the four entry points)

TermMeaning
AndroidManifest.xmlThe app's declaration to the OS: which components exist, what permissions they need, and what they can be started with. If a component isn't declared here, the system can't run it.
ActivityOne screen the user interacts with. This app has exactly one (MainActivity), a "single-activity" app — screens are Compose destinations, not more Activities.
ServiceBackground work with no UI. FokusService owns the timer engine, notification, and overlay. "Foreground service" = must show a persistent notification so the user always knows it's running.
BroadcastReceiverA listener for system-wide events delivered as Intents. BootReceiver restarts the service after reboot.
ContentProviderShares app data with other apps. Not used in fokus — listed here so you recognize it.
IntentAn asynchronous message describing an action; the OS uses it to start activities, services, and receivers. Here intents carry action strings like ACTION_START to the service.
PendingIntentA permission token for "do this later on my behalf" — used by notification buttons so the service/activity can be triggered even when the app isn't running.
intent-filterA manifest declaration of what intents a component accepts (e.g. MAIN/LAUNCHER makes MainActivity the launcher screen).
PermissionSystem-granted capability (e.g. POST_NOTIFICATIONS, SYSTEM_ALERT_WINDOW). Declared in the manifest; some must also be requested at runtime from the user.

Architecture & state

TermMeaning
LayerA slice of the app with one job: UI (Compose), state holders (ViewModel), and data/business logic (engine + repository). Fokus follows the official "layered" guidance.
Unidirectional data flowEvents flow one way (UI → logic), state flows back the other way (logic → UI). The UI never mutates state directly.
Single source of truthOne owner for each piece of state. In fokus, TimerEngine owns all timer state; nothing else stores a copy.
ViewModelA state holder that survives configuration changes (rotation) and exposes state to the UI. TimerViewModel bridges UI and service.
AndroidViewModelA ViewModel that receives the Application context, used when you need context (e.g. to bind a service).
SnapshotAn immutable description of the state at one instant. TimerEngine.Snapshot carries phase, running, remaining time, progress.
StateFlowA reactive value holder: readers always get the latest value, and it replays the current value to new readers. The service exposes state: StateFlow<Snapshot>.
MutableStateFlowThe writable side of a StateFlow; only the owner writes to it (_state), others read the immutable state.
FlowA cold stream of values, like a reactive iterable. Settings are exposed as a Flow<AppSettings> that emits on every change.

Jetpack Compose

TermMeaning
ComposableA function annotated @Composable that describes UI. Think "UI as a function of state".
RecompositionWhen the state a composable reads changes, Compose re-runs it to produce new UI. This is how screens update themselves.
collectAsStateConverts a Flow/StateFlow into Compose state; the composable recomposes whenever a new value arrives.
rememberHolds a value across recompositions so it isn't recomputed every time.
ScaffoldA standard app frame: top app bar, content area with padding. Used in TimerScreen and settings.
ModifierChained layout/styling parameters on a composable: Modifier.fillMaxSize().padding(24.dp).
MaterialTheme / FokusThemeGlobal colors/typography. The app wraps everything in its own FokusTheme (theme package).

Concurrency (coroutines)

TermMeaning
CoroutineA suspendable computation — like a thread but cheap and structured. The service runs one forever to tick the timer.
CoroutineScopeThe lifetime container for coroutines; cancelling the scope cancels its work. FokusService owns a scope cancelled in onDestroy.
SupervisorJobA job that isolates failures: one child coroutine failing doesn't cancel siblings.
DispatchersWhich thread a coroutine runs on — Main (UI), IO (disk/network), Default (CPU).
delaySuspends the coroutine without blocking the thread. The service ticks every 250 ms using delay(250).
collectSuspends, consuming each emitted value of a Flow/StateFlow (e.g. the service collecting settings changes).

Persistence

TermMeaning
DataStoreModern async key-value storage. SettingsRepository wraps a Preferences DataStore named "settings".
Preferences keyA typed key like intPreferencesKey("focus_minutes") that DataStore reads/writes.
SharedPreferencesOlder, synchronous key-value storage. Used here only for the session snapshot ("session") so the timer survives process death.
deadline-based countdownStore when a session ends (wall-clock), not how much time is left, so a killed process still counts correctly. Sessions older than an hour or pre-reboot are discarded.

Service wiring & system bits

TermMeaning
Bound serviceA service another component connects to for an API. The UI binds to FokusService via a Binder to call start/pause/skip.
BinderThe local interface object passed over a ServiceConnection; FokusService.LocalBinder hands back the service instance.
ServiceConnectionCallback pair (onServiceConnected / onServiceDisconnected) used with bindService.
START_STICKYReturn value from onStartCommand telling the OS to restart the service after it's killed (if there's work to resume).
Lifecycle / LifecycleOwnerThe state machine of a component (created → started → resumed → … → destroyed). Compose observes it to react to app lifecycle events.
WindowManager overlayA window drawn over other apps. OverlayController renders the break overlay via a ComposeView added with TYPE_APPLICATION_OVERLAY.
SystemClock.elapsedRealtimeMonotonic clock that counts even in deep sleep; used to detect reboots (it resets to 0).
Clock injectionPassing () -> Long as the "now" source so TimerEngine is testable with a fake clock — zero Android dependencies.
Navigation 3Jetpack's newest navigation library. Routes are typed keys (Timer, Settings), composed with NavDisplay + entryProvider and a back stack.
